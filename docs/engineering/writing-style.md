# 文案与文档写作规范

这份规范来自 2026-10 的一次全站文案清理，以及几篇讨论 AI 写作特征的文章。目标很具体：界面文案说清用户能做什么，文档说清事实和做法，读起来像一个了解项目的人写的。

## 1. 三条主线

1. **先写具体动作**：一句话里有动作、对象、结果。读者看完知道下一步做什么。
2. **一个概念一个名字**：导航、空态、meta、manifest、文档、测试共用同一个词。统一叫法查 [术语表](../requirements/glossary.md)。
3. **先给有用的信息**：第一句直接给结论、数字、操作或限制。背景放在后面，需要时再补。

## 2. 调研结论

几篇文章的共识是：读者判断一段文字“像 AI”，主要看信息密度、具体程度、句子节奏和结构对称性。破折号是一个线索，判断时结合整段的信息密度和节奏。把注意力放在具体信息和节奏上，效果比逐词替换更稳。

| 写作目标 | 具体做法 |
| --- | --- |
| 开头直接 | 第一句给结论 |
| 信息具体 | 写对象、动作、日期、数量 |
| 节奏有变化 | 长句和短句交替 |
| 列表自然 | 列表长度随内容变化，两项、四项都可以 |
| 形容词有支撑 | 形容词后面跟一个事实 |
| 有作者判断 | 写出自己的取舍和理由 |
| 详略分明 | 重要的地方多写，次要的地方一句带过 |
| 过渡自然 | 直接换段，或者用一句具体的话过渡 |
| 标点克制 | 用逗号、句号、冒号承担停顿，长破折号留给真正的插入语 |

## 3. 界面文案

界面文案回答三个问题：这是什么、能做什么、现在是什么状态。

### 3.1 首页和功能入口

- 徽标：个人推文归档
- 正文：一位推主发过的推文、图片和视频，按时间排在这里。想翻的时候，随时回来。
- 功能卡：多个归档用户 / 连续阅读 / 搜索和筛选 / 那年今日

功能卡的标题用名词短语，描述写用户动作：

| 标题 | 描述 |
| --- | --- |
| 多个归档用户 | 在侧边栏换一个人，时间线、媒体和搜索都会跟着换。 |
| 连续阅读 | 滚到底自动加载下一页；也可以用分页器跳到某一页。 |
| 搜索和筛选 | 按关键词搜全部推文，也可以限定日期范围或某个用户。 |
| 那年今日 | 看看往年今天发过什么，按年份排好。 |

### 3.2 状态和空态

空态说清当前状态，再给一个可执行的下一步：

- 还没有归档任何用户
- 这里还没有图片或视频
- 输入关键词开始搜索
- 没有找到匹配的推文。换个关键词试试

错误态说清发生了什么，再给动作：

- 加载失败
- 请检查网络后重试。
- 重试

### 3.3 术语

导航和按钮用短词，正文用具体词。同一个概念在整站保持一个名字：

| 概念 | 统一叫法 |
| --- | --- |
| 离线数据集合 | 归档 |
| 推文的回复 | 回复 |
| 转推动作 | 转推 |
| Twitter 内容 | 推文 |
| Instagram 内容 | 帖子 |
| 往年同月同日 | 那年今日（功能名）、往年今天（正文） |
| 图片/视频页 | 媒体（导航）、图片和视频（正文） |
| 站点入口 | 首页 |
| 浏览方式 | 无限滚动 + 翻页 |

## 4. 文档

文档服务两类读者：需要了解系统的人，和需要改代码的人。

- **第一段写任务或事实**：读者打开文档，第一眼看到最有用的信息。
- **标题用中文**：API 名、类型名、文件路径保留英文。
- **概念第一次出现时给一句解释**：后文直接用统一叫法。
- **表格用于比较，段落用于解释**：需要展开因果和取舍时用段落。
- **保留判断**：写清为什么选这个方案、放弃了什么、代价是什么。
- **保留具体细节**：版本号、日期、文件路径、命令、数量，都是读者能核实的信息。
- **活文档按本规范写，历史记录保留原貌**：开发日志、归档、复盘记录保留当时的写法，方便回看决策过程。

## 5. 落地流程

文案和文档变更按这个顺序走：

1. 先改 `docs/Specification.md` 里的行为或定位描述。
2. 再改界面字符串（`apps/web-react/app`）。
3. 同步更新测试断言和 VRT Linux 基线（`update-screenshots.yml`）。
4. 在 `docs/requirements/glossary.md` 补上新的统一叫法。
5. 新文档按本规范写，历史记录保持原样。

## 6. 提交前自查

- [ ] 第一句给了结论、数字或操作
- [ ] 每段有一个具体对象或动作
- [ ] 标题能独立看懂
- [ ] 同一概念全篇用同一个词
- [ ] 句子长度有变化
- [ ] 形容词后面跟着事实
- [ ] 文档里有作者自己的判断或取舍
- [ ] 文案变更同步了规格、测试和 VRT
