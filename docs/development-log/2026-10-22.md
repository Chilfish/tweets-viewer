# 2026-10-22

## 每日抓取代理配置改由订阅动态生成

10/20、10/21 两次定时任务失败（issue #15 / #16）：所有请求 `ERR_SOCKET_CLOSED`、`fetchedUsers: 0`，mihomo 日志是 `dial PICK ... error: failed to create session: dns resolve failed`。数据库与 `TWEET_KEYS` 都正常，根因是 `MIHOMO_CONFIG_B64` 里 9/13 固化的节点域名已失效。

### 做法

- 新增 `apps/scripts/src/prepareMihomo.ts`：读取订阅返回的完整 Clash YAML，只保留香港节点和订阅里的 `dns`，补一个 `PICK` select 组与 `MATCH,PICK` 规则，并写出默认节点名。
- `fetch-daily.yml` 每次运行先按 `MIHOMO_SUB_URL`（secret）拉订阅（订阅端是自签证书，`curl -k`），再生成 `/tmp/mihomo/config.yaml`；不再读取 `MIHOMO_CONFIG_B64`。
- 订阅的 `nameserver-policy` 只覆盖部分节点域名，脚本把本次节点的域名补进同一组 DoH —— 否则 runner 用默认 DNS 解析节点域名可能失败。
- 订阅会按 UA 过滤线路（`clash.meta` 下会过滤掉 10 条 anytls），默认节点按 `香港HK-A → 香港HKT-A → 香港HK-HY2 → 同地区 anytls/hysteria2 → 首个香港节点` 选取。
- 订阅里的节点名/域名以后变化时无需再手工更新 secret；节点顺序或可用性变化时，默认节点会自动跟着走。

### 验证

- `bunx eslint apps/scripts/src/prepareMihomo.ts --max-warnings=0` 通过
