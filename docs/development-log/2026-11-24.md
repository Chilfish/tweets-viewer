## 升级 devkit 0.2.0：环境文件分层 + 抓取并发收敛到 pipeline

`@chilfish/devkit` 0.2.0 移除了 `applyOnlineEnv` / `readOnlineTarget`，改成 `.env` → `.env.dev` / `.env.prod` 三层文件；同时新增 `@chilfish/devkit/pipeline`。原先「一个 `.env` 装本地与线上配置、`DATABASE_URL_REMOTE` 另存线上库」的做法失效，顺手把两处手写并发循环也换掉。

### 环境文件

- 新增 `env.layer.ts`：`.env` 打底，`LOCAL=1` 叠加 `.env.dev`，否则叠加 `.env.prod`；后面的覆盖前面的，进程环境优先。`LOCAL` 只看进程环境与基础文件，避免模式文件自我递归判定。
- `env.server.ts`、独立脚本与 CLI 共用同一套分层：CLI 由 `buildCli` 调用 devkit 的 `loadEnvFile`，`dailyUpdate` / `fetch-tweet-daily` 入口先 import `lib/load-env.ts`。
- `bunfig.toml` 设 `[env] file = false`：关掉 Bun 自动加载 `.env`，否则 Bun 先把基础文件写进 `process.env`，模式文件就覆盖不上。
- `.gitignore` 增加 `.env.*`；`.env.dev` / `.env.prod` 与 `.env` 一样不入库。
- 删掉 `apps/server/index.ts` 里孤立的 `import 'dotenv'`：它按 `apps/server` 的 cwd 找 `.env`，从来没有命中，只会和统一分层混淆。
- 部署只认 `.env.prod` 的 `DATABASE_URL`，本机地址直接拒绝；构建前把 `.env.prod` 的值写回进程并清掉本机代理/存储变量。
- `resolveRemoteDatabaseUrl` 改为先读 `.env.prod` 文件、再回落到进程环境里的非本机地址；本地模式下 `process.env.DATABASE_URL` 已被改成本机库，不能拿来当线上目标。
- 本机 Neon 代理固定 4445（4444 常被同机其他 devkit 项目占用），部署扫描同时拦截 4444 / 4445。

### 并发

- 删除 `forEachConcurrent`，`runBoundedStage` 薄封装 `runPipeline`：单阶段、进程内 handler，失败只记录不中断，调用方拿失败清单决定退出码。
- 用户级并发预算抽成 `resolveSyncConcurrency`（`SYNC_CONCURRENCY` 优先，缺省 Key 数 × 2）；多库并行时 `shareConcurrency` 按库数均分，总在飞请求不随库数翻倍。
- Key 级中止仍只停止派发新用户：`runBoundedStage` 增加 `shouldStop` 检查，已在跑的用户会把当前请求与入库做完；硬取消的 `signal` 保留给确实需要中断的调用方。
- 进程级请求闸门保留，跨阶段共享同一批 Key。
- `downloadExportMedia` / `uploadAccountMedia` 同样改用 `runBoundedStage`，下载请求同时接受取消信号与超时。
