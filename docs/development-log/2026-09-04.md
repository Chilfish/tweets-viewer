# 2026-09-04

## 滚动续载同步 URL 页码（page 与 cursor 双机制收敛）

**背景（用户实测反馈）**：无限滚动追加下一页时走 keyset cursor 拉取，但 URL `page` 不更新——翻到很后面了 URL 还停留在之前的页面（如始终 `?page=1`），分页器显示也停在锚点页，刷新/分享无法定位当前阅读进度。`page` 与 `cursor` 两个分页机制并存但各管各的，状态载体与实际进度脱节。

**修订决策**：滚动续载仍然 keyset cursor 拉取（4A 深翻页不退化），但每成功续载一页后用 `history replace` 把 URL `page` 同步为**已加载页数**——URL 如实反映阅读进度，且不产生历史记录（返回键不受影响）。`page` 依旧兼任定位锚点（刷新/跳页 → loader 按 page 拉取并替换列表）。

- **`app/lib/paginated-stream.ts`**：`StreamState` 新增 `loadedPages`；`applyLoaderPage` 恒对齐 URL `page`（替换/顺序追加都收敛到 `page`），`applyFetchedPage` 续载成功 `+1`。
- **`app/hooks/use-url-paginated-stream.ts`**：`loadMore` 成功后在**发起时刻 URL 页码未被用户改动**的前提下 `setSearchParams(replace)` 同步 `page = loadedPages`；若续载期间发生了跳页/筛选（URL 被用户接管）则丢弃该次追加/不抢写 URL，避免旧游标续载污染新流、旧页码覆盖新跳页。
- **五条路由（tweets/media/search/last-years-today/ins）**：列表容器 key 从 `searchParams.toString()` 改为 filterKey（`name-reverse-start-end-noReplies` 之类）——滚动同步页码不会再触发整页重挂载闪动（5B-3 的"追加不整屏闪动"保住了）；跳页/筛选变化仍会换 key 重挂载淡入。副作用：纯跳页（页码变化）不再整容器淡入，但新 page 条目各自 `slide-in-from-bottom`，视觉反馈仍在。
- **契约测试**：`paginated-stream.test.ts` 补 `loadedPages` 断言（替换→=page / 顺序追加→=page / 续载→+1）。
