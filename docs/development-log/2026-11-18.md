## 新增 IG 归档账号的标准流程

此前接入一个 Instagram 账号靠口口相传：导出、下载媒体、传 R2、改映射、入库分散在本仓库和 `gallery-dl-ins` 两个项目里，哪一步漏了都要等页面打不开才能发现。这次把它写成 [engineering/ig-archive-onboarding.md](../engineering/ig-archive-onboarding.md)，同时接入 `ritsu_mgmg`。

- **流程文档**：五步 + 验收命令 + 踩坑表。核心顺序是「媒体先上 R2，数据后入库」，反了页面能开但图全 404。
- **`.cdn.json` 是入库输入**：原 JSON 的 `scontent-*.cdninstagram.com` 链接带 `oe=` 过期时间，几小时后 403。`download-media.ts` 产出的 `.cdn.json` 把媒体地址改写成 `s3.chilfish.top`，这一步不能跳。
- **头像平铺**：帖子媒体在 `instagram/<用户名>/`，头像在 `instagram/<用户名>.jpg`（与目录同级）。传进目录里会 404，现有账号里 `240y_k` 等大部分是平铺，`38_385_popo` 两种都有。
- **映射先于入库**：`ins_posts.username` 是 twitter userName 且带外键，`users` 里没有这一行直接报错；当时的导入脚本缺映射时只打日志、不影响退出码，容易误判成功。
- **账号确认**：`ritsu_mgmg` 由 twitter `ritsu_yumemita` 简介里的 `t.co` 短链解析得到；该行 `daily_fetch = true`、`ins_username` 为空，属未接入状态。

## IG 归档并入本仓库：统一 CLI 与本地验证环境

`gallery-dl-ins/scripts` 的两个脚本（导出用户、下载媒体）只在那里能跑，且依赖 `../src/*` 内部路径；本地验证要直连线上 Neon。现已全部搬进本仓库：

- **一条命令**：`bun run ig ins add <账号> --twitter <userName>`，内部按 export → media → upload → import → verify 顺序执行，失败即停。
- **只消费公开包**：`createSDK` 从 `@chilfish/gallery-dl-instagram/node` 取，`ig.extract()` 拿 `directory` / `queue` / `url` 消息。`createFetchHttpClient` / `extractCsrf` 两个入口都不导出，所以用户资料改走 `/info/` 提取器，不再依赖内部 REST 客户端。
- **映射收敛到 DB**：删除 `mapping.ts`，IG→twitter 只读 `users.ins_username`；新增 `getUserByInsName` / `getDailyFetchInsUsers`。
- **本地库**：本机 Postgres + `POST /sql` 代理（`ig dev db` / `ig dev proxy`），`LOCAL=1` 时 `DATABASE_URL` / `NEON_HTTP_ENDPOINT` 强制切到本机；`DB` 仍是 neon-http 类型，代码路径与线上一致。
- **本地对象存储**：`ig dev storage` 启动 SILO、建桶并设匿名只读；`LOCAL=1` 时上传与媒体地址都指向 `http://127.0.0.1:9000/tweets-viewer`，与线上 R2 共用同一份 `aws4fetch` 签名代码。
- **`ins add` 补上上传步骤**：export → media → upload → import → verify，媒体先落存储再入库，避免导完一堆 404。
- **命令契约**：`CommandSpec` + 全局 `--json` / `--quiet` / `--dry-run` / `--log-level` / `--log-file`，退出码 0/1/2/3，信封 `meta.mode` 区分 local/remote。
- **每日增量**：`dailyUpdate.ts` 的 IG 步骤恢复，改调 `syncInsAccounts()`；账号失败计入结果并让目标库显红。

**顺带修掉一个迁移缺口**：`users.daily_fetch` 只存在于 `schema.ts`，6 个迁移里都没有，空库跑 `db:migrate` 会缺列。新增 `0006_add_daily_fetch.sql`（幂等）。
