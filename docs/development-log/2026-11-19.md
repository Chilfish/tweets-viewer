## 升级 gallery-dl-instagram 0.2.7：用户 feed 改走 doc_id GraphQL

上游 v0.2.7 修复了用户 feed 的 REST 端点退役问题（[Chilfish/gallery-dl-ins#4](https://github.com/Chilfish/gallery-dl-ins/issues/4)）：帖子 / Reels / tagged / 资料改为 doc_id GraphQL 主路径，REST 与页面内嵌 payload 只作降级。此前的表现就是「取不到用户信息」，本地 11-18 的 IG 冒烟也是卡在 `users/*/info` 与 `feed/user`。

- **依赖**：`apps/scripts` 的 `@chilfish/gallery-dl-ins` 从 `^0.2.6` 升到 `^0.2.7`。
- **共享会话 token**：`createSession` 改为返回 `IgSession`（`sdk` + `state`）。`csrfToken` / `wwwClaim` / `lsdToken` 由父子提取器共用，子类不再各自拉首页换 lsd、重复请求。
- **提取器构造**：根提取器（`InstagramUserExtractor`）与 `/info/`（`InstagramInfoExtractor`）按 SDK 内部的构造方式直接实例化，统一注入 `state`；`queue` 子提取器走同一份配置。原来的 `sdk.extract()` 无法传 `state`，已移除。
- **调用方**：`openSession()` 返回 `IgSession`，`runExport` / `collectUserPosts` / `collectUserInfo` 的入参同步改名。

## Twitter 数据层切换到 `@chilfish/tweet@0.2.0`（归档 JSON 结构不变）

**背景**：`packages/rettiwt-api` 与上游 [tweet-sdk](https://github.com/Chilfish/tweet-sdk) 同源，字段契约已经分叉。上游 0.2.0 补齐了抓取 / 解析 parity（互动计数、`parent_id`、卡片零宽字符清洗、`TwitterAPIClient` 运行时导出、Bun 原生代理）并已发布 npm。

**决策**：运行时改用 `@chilfish/tweet`，**归档 JSON 仍是现有 snake_case 契约**；在本仓库做一次边界映射，不改 DB / server / web-react。

- **依赖**：`apps/scripts` 新增 `@chilfish/tweet@^0.2.0`；`packages/rettiwt-api` 暂时只作为 `EnrichedTweet` / `EnrichedUser` 的归档类型来源，运行时 import 全部切走。
- **边界映射**：新增 `apps/scripts/src/lib/tweet.ts`：
  - `readTweetKeys()`：`TWEET_KEYS` 为空直接报错。SDK 对空 key 会静默退化成 guest，必须在入口保持 fail-fast。
  - `toArchivedTweet()` / `toArchivedTweets()`：camelCase → 归档 snake_case，递归处理引用推文与 `space.host`。
  - 映射字段：`mediaDetails → media_details`、`quotedTweet → quoted_tweet`、`quotedTweetId → quoted_tweet_id`、`retweetedOriginalId → retweeted_original_id`、`isInlineMedia → is_inline_media`、`*Count → *_count`、`user.id → user.id_str`、`space.host.id → id_str`；`parent_id` 直传，`article` / `__typename` 丢弃。
- **错误**：`RettiwtAuthError` / `RettiwtRateLimitError` → SDK 的 `AuthError` / `RateLimitError`；`PoolExhaustedError`（网络类，`status` 为空）不触发整轮 abort；`NotSupportedError` 由 key 校验兜底。
- **代理**：`new RettiwtPool(keys, { proxy })` 在 Bun 下走原生 `fetch({ proxy })`，CI 的 `TWEET_PROXY` 继续有效。核心入口的 `proxy` 是 Bun-only，不能用 Node 跑这些脚本。
- **cursor**：`TwitterAPIClient` 仍返回 `{ tweets, cursor }`；`writeCursor` 只依赖 `{ cursor?: string }`，不混用根入口 `TwitterClient` 的 `{ nextCursor }`。
- **口径变化**：上游 `retweetCount` 取 `legacy.retweet_count`，旧 fork 取的是 `legacy.quote_count`（历史 bug）。新入库数据从此按真实转推数；存量数据无法回填（未保存 raw），UI 新旧数据会存在口径差，已知并接受。

## 修线上 API 500：本地配置被发布进 Worker

线上 `/v3/users/all` 持续 500，日志只有 `NeonHttpPreparedQuery.queryWithCache`。`wrangler versions view` 暴露出真正原因：Worker 的 vars 是 `postgres://postgres@localhost:5432/tweets_dev` 与 `http://127.0.0.1:4445/sql`——`.env` 处于 `LOCAL=1` 时构建，`nitro.config.ts` 把值写进了 `wrangler.vars`。

- **部署收口**：`bun run deploy` 改为 `ig deploy`，固定按线上构建。`readOnlineTarget` 取 `DATABASE_URL_REMOTE`（本机地址直接拒绝），清空 `apps/server/.output` 后从零构建。
- **产物扫描**：新增 `apps/scripts/src/lib/deploy-scan.ts`，产物里出现 `DATABASE_URL` / `TWEET_KEYS` / `NEON_HTTP_ENDPOINT` 或本机库 / 代理 / 对象存储地址就中止；OpenAPI 文档里的 `localhost:3000` 不算。
- **构建守卫**：`nitro.config.ts` 在 `LOCAL=1` + 生产构建时直接抛错；线上不再写 `vars`。
- **凭据迁移**：`DATABASE_URL` / `TWEET_KEYS` 改成 Worker secret；删掉遗留的 `apps/server/wrangler.json`（nitro 会用 `defu` 合并它）。
- **二次故障**：改 secret 后仍 500，错误落在 `index.mjs:481`。`index.ts` 写的是 `process.env.X || c.env.X`，而 Nitro 只调 `app.fetch(request)`，Hono 的 `c.env` 是 `undefined`。之前 vars 存在时靠短路绕过，现在必然崩。改可选链，并让 `createDb` 在缺 `DATABASE_URL` 时报明确错误。
