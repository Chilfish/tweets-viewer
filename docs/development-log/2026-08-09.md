## P2-3 补 web UI 测试完成

- **基础设施**：装 @testing-library/react + jest-dom + user-event + jsdom（devDeps）；`vitest.config.ts` 拆为两个 project —— `unit`（store/lib/组件测试，jsdom + jest-dom setup）与 `stories`（addon-vitest portable stories，story glob 取自 `.storybook/main.ts`）
- **关键踩坑**：
  - `@storybook/addon-vitest` 的插件导出是 `@storybook/addon-vitest/vitest-plugin`（非文档常见的 `/plugin`）
  - **storybookTest 插件会覆盖 `test.include`**（启动警告明确提示），常规测试必须与 story 测试分到不同 vitest project，否则 logic 测试全被吞
  - Vitest 4 的 workspace 用 `test.projects`（不再是 `defineWorkspace`）；`coverage` 是根级选项，不能放子项目
  - @testing-library/react 自动 cleanup 依赖全局 `afterEach`，vitest 关 globals 时不生效 → setup 里显式 `afterEach(cleanup)`，否则 DOM 泄漏导致「匹配到多个元素」
  - 子项目不继承 root `resolve.tsconfigPaths`，需每个 project 显式加
- **组件测试**：`MyTweet`（正文/作者 header/转推/媒体 alt/链接卡/引用推）+ 首页入口（user-entry 继续浏览/最近/归档/空态/水合前占位 + memo-entry 目标用户解析）。断言技巧：name 链接可访问名含 VerifiedBadge 的 aria-label（「立石凛 Verified account」），用正则锚定
- **踩坑提示**：vitest 报错「Failed to resolve import ~/...」= 子项目缺 `resolve.tsconfigPaths`；「Found multiple elements」= cleanup 未生效
