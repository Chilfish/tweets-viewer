# 2026-09-14

## 定时抓取 403 排查：出口改走代理

`fetch-daily.yml` 的 `run 34775123646` 里 18 个用户全部 `403 Forbidden`。**不是 Key 过期**：用同一批 Key 在本地打同一接口全部成功、历史 100 次运行仅此一次 403、`TWEET_KEYS` secret 在失败前 3 小时刚更新。真实原因是 **X 拒绝 GitHub runner 的出口 IP**。

排查过程中踩了一个新坑并已沉淀 [postmortem 006](../postmortem/006-x-403-datacenter-egress.md)：本机跑着 Clash TUN 时，用来逐节点验证的 mihomo 测试实例 DNS 被外层 fake-ip 接管（`[DNS] a.mjanyt.com --> [198.18.0.9]`）、出站被二次跳转，据此得出的「哪些节点可用」结论**全部不可信**（我先给出、后自己推翻）。跨环境的链路问题只能在目标环境验证。

### 做法

- **出口代理**：`fetch-daily.yml` 起 mihomo sidecar。二进制按 `MIHOMO_VERSION` 走 `actions/cache@v6` 缓存（避免每次下 17MB），配置从 `MIHOMO_CONFIG_B64` secret 还原（订阅原文 220KB 超 GitHub secret 48KB 上限，裁剪成 ~1.3KB 只留候选节点 + `MATCH`），出口节点用 `PROXY_NODE` 固定。启动失败直接让步骤失败 —— 代理端口死掉时抓取会报 `ECONNREFUSED`，**不会静默跌回直连**（那样只会拿到同一个 403）。
- **`RettiwtPool` 支持代理**：`new RettiwtPool(keys, { proxy })` 透传给 `RettiwtConfig`（`proxy` 同时作用于 `x.com/home` 抓取与 GraphQL 两步）。
- **临时探针**：新增 `workflow_dispatch` + 分支 `push` 触发的 probe workflow，在 runner 上逐节点打 exit IP / `x.com/home` / 真实 timeline。结论：**7/7 节点全部可用**（含走 UDP 的 hysteria2，说明 runner 出站 UDP 无问题），anytls 与 hysteria2 最快（~1.8s），vmess 4-5.5s。验证完成后探针已删除（保留在 PR 历史中可取回）。

### 验证

- 逐节点实测（runner）：exit IP 与 `x.com/home` 200 + `rettiwt OK tweets=20`，7/7 ✅
- 反面对照：`proxy` 指向死端口时全部 `ECONNREFUSED`，证明该选项确实生效、不会静默回退 ✅
- 真实 daily job（`run 34778050003`，分支上 dispatch）：**18/18 用户成功**，`Tweet daily fetch complete.`，耗时约 1 分钟（对比失败时 4.5 分钟纯重试）✅

## `RettiwtPool` 错误分类硬化

原策略只有 `status === 429` 才换 Key：一把不可用的 Key 会让全部 18 个用户失败，且每次把 5 次退避跑满。

- **轮换集合扩到 401/403/429**：三者都是「这把 Key 现在用不了」。实测确认 X 对失效 cookie 返回的是 **401**（`code 32 Could not authenticate you`）而不是 403 —— 所以只补 403 是不够的。
- **类型化错误**：轮完所有 Key 仍失败时抛 `RettiwtAuthError`（401/403，带真实 `status`）或 `RettiwtRateLimitError`（429），并把原始 `TwitterError` 挂在标准 `cause` 上，错误明细不会丢。
- **快速中止**：`fetch-tweet-daily` 遇到上述类型化错误（或裸 401/403/429）立即中止本轮抓取，不再逐用户重试。
- **明细入日志**：`fetch-timeline-error` 补 `details`（类型化错误取 `cause.details`），下次能直接在日志里区分「出口被拦」与「凭据失效」。

### 验证

用保留 cookie 结构、仅篡改 `auth_token`/`ct0` 的坏 Key（`twid` 不动，`getUserId` 仍可解）驱动真实请求，四个 case 实测：

| case | 期望 | 结果 |
|---|---|---|
| 单个真 Key | 成功 | `OK tweets=20` ✅ |
| 单个坏 Key | 轮换后抛类型化错误 | `RettiwtAuthError status=401`，`cause.details` 含 `code 32` ✅ |
| 坏 Key 在前 + 真 Key | **轮换后成功**（旧代码此处失败） | `OK tweets=20` ✅ |
| 两把坏 Key | 轮完两把后抛类型化错误 | `RettiwtAuthError status=401`，2 次 `Rotating...` ✅ |

## IG 那步暂时停用
