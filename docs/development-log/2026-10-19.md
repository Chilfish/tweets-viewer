## `DATABASE_URL` 支持多地址：每日抓取对多库并发更新

线上 worker 指向 `ep-empty-pine-…`、本地 `.env` 指向 `ep-old-haze-…`（见 [09-17 日志](2026-09-17.md)），
两个归档库各自维护自己的 `daily_fetch` 用户集，此前一次 cron 只能更新其中一个。

- **`DATABASE_URL` 逗号分隔多地址**（首个为主库），与 `TWEET_KEYS` 的 CSV 约定一致；
  地址内若含逗号需写成 `%2C`。
- **`dailyUpdate.ts` 按地址并发**：`Promise.allSettled` 对每个库各跑一轮完整更新（Twitter；IG 恢复后同）；
  一个库连不上/失败不影响其他库继续更新，但**任一库失败进程即 exit ≠ 0**，cron 显红。
- **`parseDatabaseUrls()` 下沉 `packages/shared`**（纯函数 + 5 个单测）：去空白、丢空项、去重（同一个库不会被抓两遍）。
- **`env.server.ts`**：`DATABASE_URL` 改为「CSV 逐项 `z.url()`」校验，`env.DATABASE_URL` 收敛为主库（首个地址），
  新增 `DATABASE_URLS` 全量导出 —— 因此 API / drizzle-kit / 单库脚本**零改动**，也不会被多地址配置带崩。
- **`fetchTweetDaily()` 参数化**：`{ databaseUrl, label }` 由入口逐个传入，不再读模块级全局库，
  因此多份调用可安全并发；返回 `TweetDailyResult`（`ok` / `fetchedUsers` / `failedUsers` / `writeFailedUsers` / `aborted`），
  退出码交给入口统一决定（多库才谈得上聚合判定）。
- **日志按库区分**：新增 `db` 字段，标识只取主机名首段（`1.ep-old-haze-a1b2c3`），**不打印含密码的连接串**。
- **顺带修两处「假绿」**：
  - `DATABASE_URL` 缺失/为空，从「跳过 + exit 0」改为直接失败（exit 1）——一个库都没更新不该显成功。
  - 推文入库（`createTweets`）失败此前只打日志、不影响退出码，现计入 `writeFailedUsers` 并让进程显红；
    多库场景下这正是「某个库静默过期」的入口。

**取舍**：每个库各自抓一遍 Twitter，请求量随库数线性增长（共享同一个 `RettiwtPool` Key 池）。
若多库用户集高度重合，可改成「抓一次、并发写多库」；本次没做，避免动 `fetch-tweet-daily` 的抓取主流程。
