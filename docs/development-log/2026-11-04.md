## 日期范围筛选与排序统一到事件时间（issue #19）

**背景**：`/v3/tweets/get/:name` 的 `start` / `end` 用原推 `createdAt` 过滤，排序和 `nextCursor` 却用排序键 `COALESCE(retweeted_original_id, tweetId)`。两处不在同一时间域：当天转发的旧推在当天范围里查不到；按原推日期查又会把跨年转推混进旧年份，并因排序键较新排到最前。

**改动**：

- `packages/database/modules/tweet.ts` 新增 `dateRangeToSortKeyRange()`：把 `start` / `end` 映射为排序键的 snowflake 闭区间（UTC 自然日，`end` 含当天）。日期范围改用它过滤，与排序 / 游标同域，并能命中 `idx_tweets_username_sortkey`。
- `getTweetsByDateRange()` 与 `getMediaTweets()` 的日期范围都切到排序键区间。媒体端点本来就排除转推，行为不变，只是复用同一口径。
- `getTweetsYearStats()` 改为按排序键对应的 UTC 年份分组：转推计入转发发生的年份，年份统计与可筛出的条数一致。
- 文档同步：`Specification.md` §4.1 写明事件流语义，`API_DOCUMENTATION.md` 补充 `start` / `end` 与 `stats` 口径，`openapi.ts` 的日期参数说明同步；`EnrichedTweet.retweeted_original_id` 补注释，说明它存的是转推动作 id 而非原推 id。
- 新增 `dateRangeToSortKeyRange()` 单测：真实转推 id 落在动作当天、按天连续、跨天闭区间。

**验证**：

- `bun --cwd packages/database test` 18/18 ✅
- `bunx eslint packages/database/modules/tweet.ts packages/database/__tests__/tweet.test.ts` ✅
- `bunx tsc --noEmit -p packages/database/tsconfig.json`：仅剩 `rettiwt-api` 既有的 DOM 类型报错，与本次改动无关。

**待办**：线上数据需部署后按 issue 复现步骤回归（当天 `start=end` 应包含 4 条当天转推；2025-05-21 范围不再出现 2026 的转推）。

## 清理未使用的 happy-dom 依赖（Dependabot 3 条告警）

**背景**：Dependabot 对 `packages/rettiwt-api/package.json` 的 `happy-dom@20.1.0` 报了 3 条告警：

- GHSA-c8p4-j97h-3vg8（high）：解析不可信 HTML 时 iframe / stylesheet 触发 SSRF
- GHSA-5fpq-26gf-qwcr（medium）：`Domain=` 匹配缺少 DNS 标签边界，攻击者可伪造 cookie 作用域
- GHSA-834v-8h66-3h79（high）：import alias 未清理，可执行宿主代码

这个 fork 的 HTML 解析已统一用 `linkedom`（`services/public/FetcherService.ts` 与 `__tests__/transaction-document.test.ts`），源码里没有任何地方引用 `happy-dom`，属于上游遗留依赖。

**改动**：

- `packages/rettiwt-api` 删除 `happy-dom` 运行时依赖，`bun install` 刷新 `bun.lock`，连带移除其专属的 `@types/node@20` / `@types/ws` / `whatwg-mimetype` 等传递依赖。
- 锁文件落到默认分支后，3 条告警自动关闭。

**验证**：

- `bun --cwd packages/rettiwt-api test` 25/25 ✅
- `bun --cwd packages/rettiwt-api typecheck` ✅
- `packages/rettiwt-api` 属于 lint 豁免目录（`eslint.config.mjs` 的 `ignores`），依赖变更不影响 lint 门禁
