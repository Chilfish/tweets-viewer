# 2026-10-31

## VRT 门禁降噪：文案遮罩 + 环境固定

**背景**：`visual` job 连续两次红，失败截图为 `feed-status` 的 `dark full-page-error` / `dark tail-error`，像素数与 2026-10-28 那次完全相同。根因是 `a534839 refactor(copy)` 改了错误态文案与按钮，但 linux 基线没重生成；同一个改动在 light 主题下差异不足 1% 被放过、dark 超阈值被拦。详见 [postmortem 007](../postmortem/007-vrt-copy-churn-stale-baselines.md)。

**改动**：

- `app/test/vrt.tsx` 新增 `maskText()` / `expectScreenshot()`：用 `toMatchScreenshot` 的 `screenshotOptions.mask` 遮掉 `p`、`button` 与 `[data-vrt-mask]`。Vitest 5 的公开类型尚未暴露 `mask`，集中做一次类型断言并注明上游公开后删除。
- `feed-status.vrt.test.tsx` 改用带遮罩的断言；`FeedStatus` 的两处重试按钮用 `[data-vrt-mask]` 包成整宽行（`flex w-full justify-center`），避免遮罩框随按钮文案长短漂移。视觉不变。
- 新增 `components/__tests__/feed-status.test.tsx`（RTL，10 项）：覆盖 idle / fetching 无内容返回空、默认与自定义空态文案、全页错误文案与重试回调、尾部加载/失败/耗尽文案、`hideEmptyState`。
- `ci.yml` 的 `visual` job 与 `update-screenshots.yml` 固定 `runs-on: ubuntu-24.04`、`bun-version-file: package.json`，避免 runner / bun 浮动升级改变字形渲染。

**本地验证**：

- `feed-status` VRT 重建 win32 基线后 10/10 ✅；把按钮文案改成「重新加载」、错误说明改回旧长文案，VRT 仍 10/10 ✅（证明文案不再进像素门禁）。
- 把错误图标容器改成 `bg-green-500` 再跑，`full-page-error` 两个主题如期变红（证明真实视觉回归仍能抓到）。
- `feed-status.test.tsx` 10/10 ✅。

**待办**：linux 基线需走 `update-screenshots` workflow 重生成（本地 win32 基线对 CI 无效）。
